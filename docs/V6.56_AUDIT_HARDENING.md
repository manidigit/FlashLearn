# v6.56 Comprehensive Audit Hardening

## Scope
This checkpoint applies the current 6.55 codebase against the supplied 6.53 audit report. Historical findings were re-checked against the current tree; only findings still present were changed.

## Decisions applied
- Review queue approval semantics remain intentionally deferred; no automatic approval/import behavior was introduced.
- Quiz prompts follow the active source language.
- A quiz with insufficient distractors provides an explicit skip action.
- Weekly/Monthly correct-review scheduling is aligned to the start of the local calendar day.
- Learning and Difficulty remain independent. monthlyWrongCount and hasPathFailure remain backward-compatible persistence fields and do not influence Difficulty.
- Deleted vocabulary is soft-deleted first and periodically purged after 90 days, with the cleanup check running at most once every 30 days.
- Android automatic backup is explicitly disabled because FlashLearn owns its in-app backup/restore flow.
- Backup encryption remains a deferred, low-priority option and is not silently claimed as implemented.

## Correctness hardening
- Flashcard feedback has an explicit next-card action.
- Quiz-unavailable state has an explicit skip action.
- Active review language pair and maximum review-card setting are passed into the review engine.
- Home ready counts use the same stage, due-time, same-day lock and language-pair eligibility as the review queue.
- Home stage denominators remain total words assigned to Daily/Weekly/Monthly and match Statistics.
- Translation editing reconciles target rows by translation index and removes stale rows.
- Missing Learning/Difficulty state is self-healed when Progress Summary is calculated.
- Starter data creation is persisted as a one-time operation.

## Backup/export hardening
- Vocabulary restore preserves separate translation rows instead of joining them with slash.
- Vocabulary metadata such as category, favorite, dates, notes, pronunciation, example, grammar and correction metadata is preserved when available.
- Typed Progress backup includes settings and does not overwrite local settings with older timestamps; data-version keys are excluded from restore.
- Restore validation rejects invalid enum values before mutation.
- CSV/XLSX exports include only active concepts and escape spreadsheet formula prefixes.
- Restore input is bounded to 20 MiB at the UI file-reading boundary.

## Performance hardening
- Review candidate filtering can be applied as sets in one queue load instead of repeated difficulty/category combinations.
- Quiz distractor ranking is bounded to a smaller lexical candidate pool and the quiz bank refresh is protected against concurrent mutation.
- Progress activity calculations group review history by local date once instead of repeatedly filtering the full history.
- Content lookup has a canonical-key repository path for duplicate detection.
